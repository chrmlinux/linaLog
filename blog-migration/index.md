# elchika から GitHub Pages へ、ブログ71記事を引っ越した手順

2026年11月27日 13:44

<p><img src="../assets/rina-chan.png" alt="リナちゃん" width="240"></p>

## はじめに

技術記事は長く elchika に書いてきました。発表の場としては note も検討したのですが、note は Markdown がそのまま使えず、表（テーブル）も作れません。書きたい形で書けないのは、道具として致命的です。

そこで、記事の置き場所を GitHub に一本化することにしました。GitHub なら Markdown がそのまま通り、表もコードも思ったとおりに書けます。elchika の記事71本全部を、GitHub Pages の自前ブログ「linaLog」へ引っ越しました。この記事は、その引っ越し手順の記録です。再現できるように、手順とハマりどころを全部書きます。

## 引っ越し先の構成

| 項目 | 内容 |
| --- | --- |
| 置き場所 | GitHub リポジトリ（chrmlinux/linaLog）＋ GitHub Pages |
| 生成 | Jekyll（GitHub Pages 標準） |
| テーマ | jekyll-theme-hacker（技術系の装丁） |
| 記事の形 | 1記事1フォルダ: `<slug>/index.md` ＋ `<slug>/images/` |
| 画像 | 記事フォルダ内にローカル配置（外部参照なし） |
| 一覧 | トップに日時付き一覧＋日付ソート（新しい順／古い順） |

記事をフォルダ単位にしたのが肝心なところで、記事とその画像が1つのフォルダに閉じているので、移動も削除もフォルダごとで済みます。

## 手順

### 1. リポジトリと Pages の用意

GitHub に公開リポジトリを作り、Settings → Pages で「Deploy from a branch（main / root）」を有効化します。`_config.yml` にテーマとタイトルを書くだけで、Markdown の記事がそのままページになります。

```
theme: jekyll-theme-hacker
title: linaLog
description: 製作記事 / Project write-ups
```

フロントマターなしの .md でもページ化されるのは、GitHub Pages 標準のプラグイン（optional-front-matter など）が効いているためです。

### 2. 記事の列挙

elchika のプロフィールページは表示がページングされていて、HTML を単純に拾うと他人の記事まで混ざります。確実なのは、プロフィールが使っているユーザー専用 API（記事一覧、total 件数付き）で全件を列挙する方法でした。投稿数71件と一致するまで突き合わせています。

### 3. 本文と画像の取得

各記事は、記事詳細 API から著者自身の元 Markdown を取得しました。表示用 HTML から起こすより、元 Markdown の方がコードブロックがバイト単位で正確です。

画像はすべてダウンロードしてローカル化しました（全303点）。

- トップ画（カバー）は `images/img01` として記事先頭へ
- 本文画像は出現順に img02, img03...
- 拡張子はファイルの中身（マジックバイト）で判定
- 本文中の画像参照は相対パスへ置換し、リモート参照を残さない

### 4. 日時の復元

一覧を日付で並べるため、各記事の公開日時が必要です。elchika の記事レコードには createdAt（UTC）があるので、これを日本時間に換算して「2026年9月8日 19:25」の形で記事先頭と一覧に付けました。時刻まで入れておくと、一覧のソートが日単位でぶれません。

### 5. 記事同士のリンクの書き換え

シリーズ記事同士の相互リンクが202件ありました。リンク先は全部自分の記事だったので、elchika の URL から linaLog 内の相対リンク（`../<slug>/`）へ書き換えています。引っ越し先でリンクが完結する形です。

### 6. 罫線図のテーブル化

elchika 時代に罫線（┌─┐│）で描いた図が29ブロックありました。等幅で崩れない場所なら図のままでも良いのですが、表にできるものは表の方が読みやすく、検索にも強いです。スタック図・レイヤー図・フロー図を Markdown の表に変換しました。例えばスタック図はこうなります。

アドレス大 ↑

| 領域 | 位置・備考 |
| --- | --- |
| 呼び出し元の情報 | 直下の境界が bp (ここが基準点) |
| ローカル変数 #1 | bp-1 |
| ローカル変数 #2 | bp-2 |

変換時は、元の図のラベル（関数名・注記）が1つも欠落しないよう突き合わせて検証しています。

### 7. 仕上げの機能

素の Jekyll に、読み手向けの機能を少し足しました。全部 `_includes/head-custom.html`（テーマ標準の差し込み口）経由なので、記事ファイルを1本も汚しません。

| 機能 | 実装 |
| --- | --- |
| コードのコピーボタン | 全コードブロックの右上に「コピー」ボタンを JS で付与 |
| SNS 共有 | 記事末尾とトップに X / note / LINE / はてなブックマーク のリンク |
| RSS | 静的に生成した feed.xml（公開のたびに再生成） |
| 一覧サムネイル | トップ画を 78×44 に縮小表示。無い記事にはマスコット画像 |
| テーマヘッダー非表示 | 標準ヘッダーを CSS で消し、自前タイトルに一本化 |

## ハマりどころ

| 問題 | 対処 |
| --- | --- |
| リポジトリ作成は API からできない | 作成だけは GitHub の画面で手動 |
| 画像などのバイナリは API の push で送れない | GitHub の Web アップロード画面からフォルダごとに投入 |
| Pages の反映に時間がかかる | コミット後、数分待ってから表示確認する |
| プロフィールページの HTML に他人の記事 ID が混ざる | ユーザー専用 API で列挙する |
| X 投稿の埋め込みは移行できない | プレースホルダの1行に置換（42記事・95件） |

## 結果

71記事すべてが linaLog に移り、画像303点もローカル化が完了しました。記事は Markdown のまま Git で管理でき、表も図もコードコピーも思ったとおりに使えます。引っ越しは一度きりの作業ですが、その後の書きやすさは毎日効いてきます。
