# LinaX(cyd) ― PSRAM なしの ESP32（CYD）に載せた Linux 6.11

2026年11月21日 21:41

<p><img src="../assets/rina-chan.png" alt="リナちゃん" width="240"></p>

## 概要

LinaX(cyd) は、PSRAM なしの初代 ESP32 ボード CYD（Xtensa LX6、内蔵 DRAM 320 KB、フラッシュ 4 MB）に載せた Linux 6.11.0 です。シリアルコンソールから対話シェル `linax>` が使え、microSD カードを fstab で自動マウントしてファイルが読めます。

ESP32 への Linux 移植は既存のものがありますが、いずれも PSRAM 搭載ボードが前提です。公表されている実測では、カーネルの静的データだけで約 623 KB の RAM が必要とされていました。CYD の DRAM は 320 KB しかありません。本製作は、この「623 KB の壁」を、ツールチェーンの自前構築とカーネル構成の極限までの削減で越え、PSRAM なしの実機で対話シェルまで到達した記録です。

最終的なカーネルの静的占有は .data 68,576 バイト＋.bss 31,816 バイトで約 98 KiB（ブート時ピーク約 113 KiB）です。起動後の表示では totalram 208 kB、freeram 8 kB でした。RAM 2 KB の Arduino Uno に載せた linaX(uno) とは別系統で、こちらは本物の Linux カーネルそのものを移植したものです。

## 構成

- カーネル: Linux 6.11.0（linux-xtensa ツリー）。カーネルイメージはフラッシュ上に置いたまま実行する XIP 構成で、.data/.bss だけを DRAM（0x3FFB0000 から 320 KiB）に配置します
- ツールチェーン: crosstool-NG で自前構築（gcc 14.1.0、uClibc-ng、FDPIC 形式）
- ルートファイルシステム: romfs（フラッシュ内）。フラッシュ配置はブートローダ 0x1000／カーネル 0x40000／rootfs 0x200000 で、合計 4 MB に収めています
- init: libc を使わない自作のミニ init。後述の理由で「書き込み可能セグメントを持たない」特殊な構造にしています
- シェル: ミニ init 内蔵の対話シェル。コマンドは help、echo、ls、cat、free、uname、sh、reboot、mount、umount
- microSD: SPI3 をレジスタ直叩きする自作ドライバで SD カードを MTD デバイス "sdcard" として登録し、romfs でマウントします

## 製作過程

### DRAM への移植

土台にしたのは PSRAM 前提の ESP32 向け構成です。変更は、カーネルのデータ配置先を PSRAM から内蔵 DRAM の窓（0x3FFB0000、320 KiB）へ移すことと、CYD 用の DTS を用意することから始めました。この時点で静的占有は約 98 KiB まで下がっていましたが、問題はここからでした。

### 1 ページを巡る攻防

320 KB のうちカーネルが管理できるのは約 200 KB で、ブートが進むにつれて空きメモリは 4 KB（1 ページ）単位で削られていきます。initcall の途中で OOM になり、対策を打つたびに失敗箇所が少し先へ移る、という繰り返しでした。ビルド番号で v8 から v53 まで、この壁との戦いです。

効いた対策は、どれも「地味に 1 ページ返す」ものです。

- 不要なドライバとサブシステムを構成から外し、デバイスツリーも実際に使うノードだけに削る（UART は 0 番だけ、SPI は SD 用の 3 番だけ）
- percpu 領域の最小単位を 16 KB から 4 KB へ
- ファイル名キャッシュのオブジェクトサイズを 4,096 バイトから 512 バイトへ（長い名前は扱えなくなりますが、実用上問題ありません）
- printk のリングバッファは 1 KB（LOG_BUF_SHIFT=10）。これより小さくすると別の問題が出たため、ここが下限でした
- ワークキューの余分なワーカースレッドを、exec の直前に整理してスタックページを回収する
- コンソールを開く処理とルートマウントを、initmem 解放の後へずらす

### FDPIC と init の構造

最後の壁は init の exec でした。必要ページを数えると、mm 構造体のスラブ 1 ページ、引数ページ 1 ページ、スタック 1 ページで、空きは 1 ページしかありません。

調べると、FDPIC ローダの既定スタックサイズは 128 KB で、このままでは NOMMU では絶対にマップできません。ローダ側でスタックを 1 ページに固定しました。

さらに、init 本体から書き込み可能セグメントを無くしました。通常の FDPIC バイナリは GOT（グローバルオフセットテーブル）を書き換えるため RW セグメントを持ち、その割り当てに 1 ページ要ります。自作 init では、起動時に GOT のテンプレートをスタック上に複製してそちらを書き換える方式にし、バイナリ全体を読み取り専用の 1 セグメントだけにしました。書き込み可能な静的変数も全て排除し、バッファは関数のローカル変数に移しています。

これで v53 でシェルが起動しました。

### コンソール入力が死んでいた件

シェルは表示されるのに、キー入力が一切効きませんでした。切り分けの結果、信号は GPIO3 のパッドまで届いており、UART の受信ステータスビットも入力に追随して変化するのに、受信 FSM がバイトを生まない状態でした。内部ループバックでは受信できることも確認しました。

最終的な解決は、ドライバの初期化時に UART0 を DPORT 経由でハードリセットすることでした。ブートローダ経由で引き継いだ UART の状態が残っていたものと考えられます。リセット後は受信割り込みでバイトが届くようになりました。

なお、その直後に「バイトは届くのにエコーも応答もない」問題がもう一段ありました。原因は自作のワーカ整理コードが、tty のフリップバッファをフラッシュする unbound ワークキューのワーカーまで止めてしまったことでした。unbound プールに 1 本だけワーカーを残すよう直して、対話が成立しました（v69〜v70）。

### microSD と fstab

仕上げに microSD を付けました。当初は通常の MMC スタック＋VFAT で進めましたが、ブロック層とファイルシステムの常駐コストが大きく、initcall の途中で OOM になりました。方針を変え、SD カードを MTD デバイスとして登録し、ルートと同じ romfs でマウントする方式にしました。ブロック層・MMC コア・FAT を全て外せるため、常駐コストは最小です。

ここでも落とし穴がありました。土台にした SPI ドライバのレジスタマップが ESP32-S3 のもので、初代 ESP32 とは全く違っていたのです。転送が一切シフトしない症状からこれを突き止め、ESP-IDF のヘッダで初代 ESP32 のレジスタマップを確認して、SD ドライバは SPI3 のレジスタを直接叩く形に書き直しました。

もう 1 つ、CMD58 の OCR の読み取り位置が応答の先頭からずれていて、SDHC のブロックアドレス判定（CCS）が誤り、セクタ 0 以外が読めない問題もありました。応答オフセットを記録して相対位置で読むよう直し、全セクタの読み取りが通るようになりました。

init 側には簡易 fstab ローダを実装し、起動時に /etc/fstab を読んで自動マウントします。最終的に、サンプルイメージの 512 行のテキストファイルまで正しく読めることを実機で確認しました（v88）。診断表示を全て外したクリーンビルドが v89、表示上の改行の重なりを init 側で直した v90 が最終版です。

## Serial からのデバッグ

実機のコンソールは UART0、115,200 baud です。書き込みは結合イメージを 0x0 から書く方式で、ブートローダ、カーネル、rootfs を 1 ファイルで書き込みます。

この製作では、障害の切り分けはほぼ全てシリアルログで行いました。OOM の発生箇所は、そのイメージの vmlinux でアドレスをシンボル化して特定しています。また、QEMU（Espressif 版）でも同じイメージを動かしましたが、QEMU は実行時に設定される MMU マッピングを命令フェッチに反映しないため、カーネルへのジャンプで止まります。QEMU で止まってもイメージの不良とは限らない、というのがこの件での教訓です。

## 使い方

起動するとブートログの後にプロンプトが出ます。

```
LinaX(cyd) mini init
totalram: 208 kB
freeram: 8 kB
procs: 4
linax>
```

主なコマンドです。

```
help
ls
ls /sd
cat /sd/hello.txt
free
uname
```

microSD は、romfs イメージをカードの先頭から raw で書き込んだものを挿しておくと、起動時に /etc/fstab（`mtd:sdcard /sd romfs defaults 0 0`）で /sd へ自動マウントされます。カードがない場合はマウントを数回試して失敗表示を出し、そのままシェルに入ります。

シェルには cd や行編集はありません。コマンド入力後にプロンプトが 2 回表示されることがありますが、CR+LF の扱いによる表示上のもので、そのままにしています。
